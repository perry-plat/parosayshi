# WizPay: early solution preview

Reference reviewed 10 September 2026: [Shaun Tan, Proof](https://shaun.design/).

Observed sequence: overview and role → two specific problems → core solution flows → explanation of the old and new record structure → reflection. The deeper structural explanation follows a demonstration of what the new experience does.

Recommended adaptation for WizPay: brief product context and problem → one shared-collection solution preview → three decisions → reflection. Retain Superr styling. This is a proposed ordering, not a claim that the old modal was the solution preview Shaun's pattern calls for.

The preview should show the later shared collection design with a short explanation of amount, context and method. The three decisions then explain entry points, the limits of the first modal, and the move into a full module. Avoid duplicating the full preview image later: use the comparison or an annotated detail to teach something new.

New first-hand context from Parth: recurring payments, partial payments and partial refunds were particularly troublesome for the initial modal. This now grounds decision 2. The shown collection exploration does not by itself demonstrate a completed recurring-payment or partial-refund flow; do not present it as proof of those behaviors.

Implementation status: the three-decision version is implemented. The early solution-preview reorder remains a recommendation pending the user's response to this reference analysis.
